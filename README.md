# iM AXIS 데모

계약서와 요청서를 Studio로 대조하고, 웹에서 접수 상태·판정·근거를 확인하는 팀 데모입니다. 실제 승인·송금은 하지 않습니다.

**실행 환경은 macOS입니다. 미션 2 제출 워크플로우와 기존 팀 API 키를 그대로 사용합니다.** 워크플로우·컬렉션을 새로 만들 필요는 없습니다. 새 분석마다 해당 워크플로우의 **최신 저장 config**를 사용합니다. 팀원이 Studio 설정을 바꾸면 다음 신규 접수부터 영향을 받습니다.

## 1. 준비

- Git, Node.js 22.13.0 이상과 npm, Python 3, Poppler가 필요합니다.
- 기존 팀 Studio에 접근할 수 있는 API 키를 원준님에게 비공개로 전달받습니다.
- 인터넷 연결이 필요합니다. 실제 분석은 팀 Studio의 API 사용량에 포함되고 같은 컬렉션에 저장됩니다.

[Homebrew](https://brew.sh/)를 사용한다면 필요한 프로그램을 설치할 수 있습니다.

```sh
brew install node@22 python poppler
export PATH="$(brew --prefix node@22)/bin:$PATH"
```

## 2. 파일 받기와 최초 설정

터미널에서 실행합니다.

```sh
git clone https://github.com/chawj1234/im-axis-demo.git
cd im-axis-demo/06_시연프로그램
npm ci
cp .env.team.example .env.team.local
open -e .env.team.local
```

열린 설정 파일에서 **`UPSTAGE_API_KEY=` 뒤에 전달받은 기존 팀 키를 붙이고 저장**합니다. 나머지 연결값은 그대로 둡니다. 키가 들어간 `.env.team.local`은 GitHub에 올리지 않습니다.

## 3. 실행

앞에서 연 터미널의 `06_시연프로그램` 폴더에서 실행합니다.

```sh
npm run team:check
npm run team:demo
```

`team:check`는 설치·설정 형식만 확인합니다. API 키의 실제 접근 권한까지 확인한 것은 아닙니다. `team:demo` 실행 후 은행원·관리자 주소가 표시되면 브라우저에서 엽니다.

- 은행원: <http://127.0.0.1:3001/banker?session=team-demo-01>
- 관리자: <http://127.0.0.1:3001/admin?session=team-demo-01>

같은 접수를 확인할 때는 두 주소의 `session` 값을 같게 둡니다. 이 주소는 실행한 Mac에서만 열립니다. 종료는 터미널에서 **Control+C**입니다. 다음에는 같은 폴더에서 `npm run team:demo`만 실행하면 됩니다. Homebrew의 `node@22`를 사용한다면 새 터미널에서도 위의 `export PATH` 명령을 먼저 실행합니다.

## 4. 문서 접수와 확인

입력 PDF는 저장소의 `03_시연자료` 폴더에 있습니다. 회사·사람·계좌·금액은 가상이며, 파일명에 적힌 등급은 기대값입니다. 최신 Studio에서 확인한 실제 결과와 구분합니다.

1. 은행원 화면의 **계약 등록**에서 공통계약서 PDF를 접수합니다. 계약서는 약정서+통장사본 2쪽입니다.
2. Studio 계약등록 워크플로우의 실행 결과에서 해당 약정번호와 입력 검증 통과를 확인합니다. 접수 완료·분석 완료와 계약 기준정보 저장은 서로 다릅니다.
3. 같은 세트의 요청서 PDF를 **실행 요청 접수**에서 접수합니다. 등록한 계약과 요청서의 약정번호가 연결되어야 합니다.
4. 은행원 화면에서 진행 상태를, 관리자 화면에서 판정·등급과 제공된 근거를 확인합니다. 상세의 원문 연결에서 PDF를 확인할 수 있습니다.

PDF는 한 번에 한 개, **25MB·20쪽 이하**입니다. `단순_등급검사세트`와 `예외함정_검사세트`는 각각 자기 세트의 공통계약서를 사용합니다. 정답 JSON·안내문은 접수하지 않습니다.

## 5. 촬영 전에 알아둘 동작

- **접수 완료:** 파일을 받았다는 뜻입니다. 분석이나 판정 완료를 뜻하지 않습니다.
- **미평가:** 필수 정보 등을 확인해야 하므로 등급을 확정하지 않은 상태입니다. 정상으로 해석하지 않습니다.
- **처리 실패·처리 확인 필요:** 연결 오류나 결과가 불확실한 상태입니다. 접수 내역과 Studio 실행을 확인합니다.
- 같은 세션·접수 종류에 같은 PDF를 다시 넣으면 기존 접수로 처리하며 새 분석을 만들지 않습니다. 최신 config로 새로 분석해야 한다면 새 세션을 사용합니다.
- 종료해도 이 Mac의 `.local-private/team-demo`에 원문·접수 기록이 남습니다. 폴더를 삭제하지 않으면 다시 켰을 때 이어 볼 수 있습니다.
- 다른 Mac의 과거 접수 기록·원문은 자동으로 가져오지 않습니다. 같은 Studio 컬렉션을 쓰는 것과 웹 접수 기록을 공유하는 것은 별개입니다.
- `/preview` 주소는 예시 화면입니다. 실제 분석 결과 촬영에는 위 은행원·관리자 주소를 사용합니다.
- **질문하기:** “등급별로 결과 알려줘”, “확인 필요한 요청과 근거 알려줘”처럼 물어봅니다. 지정된 요청서 결과 컬렉션을 조회하도록 요청하며, 이 Mac의 접수 기록에만 한정하지 않습니다. 검색으로 확인한 일부 결과를 전체 결과나 오늘 처리 결과로 해석하지 않습니다.
- **등급별 보고서 작성:** 웹에서 바로 요청할 수 있습니다. **예약 보고서**는 기존 팀 Studio의 AI 동료 → 예약 작업 → **iM AXIS 등급별 문서대조 보고**에서 확인합니다. 기존 예약은 **매일 15:30(Asia/Seoul)**이며, 날짜 필터 없이 저장된 결과를 등급별로 정리하도록 설정했습니다. 예약은 Studio에서 실행되므로 웹을 켜 둘 필요는 없습니다.
- **현재 보고 기능의 확인 범위:** 예약 이름·지시문·시간 저장은 확인했습니다. 새 요청서 결과 컬렉션은 동료 참고 자료 선택 목록에 나타나지 않아 연결과 실제 보고서 출력은 미확인입니다. 접수·대조·원문 확인 흐름부터 시연하고, 보고 기능은 실제 답변을 확인한 뒤 촬영합니다. Studio 동료 응답 오류를 0건으로 해석하지 않습니다. **보고서 내용과 예약 실행 결과는 실제 출력이 확인된 범위에서만 촬영합니다.** 고객 알림·기존 n8n 기능은 이 실행 안내의 확인 범위에 포함하지 않습니다.

## 6. 문제가 생기면

- **설정 파일이 없거나 설정 항목 오류:** `.env.team.local`의 누락 항목을 확인합니다. 최신 config 모드에서는 `STUDIO_REQUEST_CONFIG_ID`·`STUDIO_CONTRACT_CONFIG_ID`를 추가하지 않습니다.
- **Python·PDF 도구 오류:** `brew install python poppler` 후 새 터미널에서 다시 실행합니다.
- **3001번 포트 사용 중:** 기존 실행을 Control+C로 종료합니다. 다른 프로그램이 쓰는 경우 설정의 `STUDIO_WEB_PORT=3002`로 바꾸고 실행 후 표시되는 주소를 사용합니다.
- **접수 내역 연결 오류:** API 키의 접근 권한과 인터넷을 확인합니다. 프로젝트·워크플로우·컬렉션 ID는 설정 예시 그대로 사용합니다.
- **PDF 접수 실패:** 파일 형식·크기·쪽수와 손상·암호 설정을 확인합니다.
- **결과가 늦거나 실패:** 목록에서 상태를 확인하고, 관리자 상세의 Studio 연결에서 실행 결과를 확인합니다. 응답을 받지 못한 접수를 반복해서 새로 만들지 않습니다.

개발 검사: `npm test`는 모의 API를 사용하며 실제 Studio를 호출하지 않습니다. 실제 API 키와 최신 저장 워크플로우의 동작은 별도 확인이 필요합니다.
